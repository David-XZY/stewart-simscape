# Development probe: reduced force-increment optimization

This folder is an isolated development implementation. It is not the frozen
Chapter 5 experiment version. The registered baseline, trained weights,
teacher data and production configuration remain intact.

## Numerical coordinates and physical decision

The physical decision is still the complete sequence of six-axis branch-force
increments. Applied force commands are accumulated and states are obtained
from the original actuator-augmented `plant.fd`. No independently planned
reference trajectory is handed to a tracking controller.

`ch5ReducedStep` is a diagnostic of straightforward 12-block (72-coordinate)
condensing. `ch5ReducedStepOsqp` changes its QP backend. Both retain a full
60-interval, 1.2-second dynamics horizon and the original physical gate.

`ch5ReducedStepFeedback` additionally preconditions the same correction by
local feedback. For an internally generated warm iterate `(Xbar,Ubar)`,

```
v_j = 160 * sum(block_increment_b, b <= ceil(j/5))
U_j = Ubar_j + v_j - K * (X_j - Xbar_j)
X_(j+1) = fd(X_j, U_j)
DeltaU_j = U_j - U_(j-1)
```

The warm state sequence comes exclusively from dynamics applied to a force
sequence. It is an optimization iterate. These 72 coordinates are a numerical
parameterization of a correction; they must not be described as 72 independent
physical input increments held constant between blocks. The full physical
increments generally vary inside a block. Their nonlinear transformation is
used when generating a trial, and the objective's input/prior terms use the
resulting physical force increments.

In the linearized condensing, `dX_(j+1)=A*dX_j+B*dU_j` and
`dU_j=M_j*dv-K*dX_j`. This avoids propagating only the open-loop `A` in the
numerical sensitivity recursion. The executed first force is checked through
the original dynamics and mesh. This implementation does not constitute a
robust stability or recursive feasibility proof.

The warm-start embedding is informed by Makarow, Roessmann and Bertram,
[Suboptimal nonlinear MPC with input move-blocking](https://arxiv.org/abs/2109.12355).
That paper's guarantees are not asserted for this diffusion/Simscape system.

## Terminal correction and rejection

Preserve and shift the complete previous sequence. Correct only its final
two 100-ms force blocks by Newton iterations for terminal velocity and static
force compatibility. This correction is never an acceptance test. The same
terminal bands, force/rate limits, conservative singularity check, collision
margin and every existing integration point remain required for full-horizon
admission. In v10/v11, intermediate execution instead checks the upcoming
physical hold and does not claim full-horizon or terminal admission.

Endpoint constraints guide the condensed QP. All internal points are audited
afterward; a rejected trial is backtracked. Endpoint linearization alone is
not claimed to guarantee safety between samples.

The restoring fallback retains a pose anchor, clips desired acceleration in
leg space, invokes the baseline safety QP with additional acceleration reserve,
then checks the next complete hold interval. All fallback, failed QP and failed
interval checks remain explicitly uncertified and are recorded.

## Scope and reproducibility

- Control execution: 0.02 s. Optimization refresh: 0.1 s, or goal/visibility change.
- Horizon: 60 intervals, 1.2 s; original internal integration mesh.
- Learned prior: existing validated seed 5101, 20 DDIM steps, four generated
  chains. This speed probe ranks four priors and optimizes one correction.
  It does not implement four independently optimized formal candidates.
- Full cost combines task, physical force/increments and learned-prior terms.
- MATLAB, model and native kernels are reused in one persistent worker.
- Cold preparation and kernel construction are separate from controller time.
- All Simscape development episodes use `CaptureErrors` and save raw records,
  prediction checks, code hashes and actual dense-grid metrics, including failures.
- Formal campaign remains unstarted pending closed-loop and timing acceptance.

Artifacts: `chapter5/artifacts/reduced_probe`. Entry functions are queued via
the existing `ch5SpeedWorker`; do not launch a fresh MATLAB for every episode.

Initial diagnostics and corrected variants are stored in separate artifact
directories. Do not pool them into one result version.

  constraints; relative differences are below 1e-10.
- `ch5ReducedAuditV4` fixes an optional-argument count error in the old probe:
  the supplied learned prior was reset to zero in posterior cost evaluation.
  QP and posterior objective now use the same physical-increment prior term.
  A nonzero-prior regression checks its exact cost contribution. Version v5's

  squared physical-increment prior proxy is integrated over time like the

## Objective screening and retained numerical seeds (v12/v13)

`ch5ReducedAuditV12` uses the same native preview and the same cost arithmetic
as v11. After any necessary terminal correction, a trial whose cost cannot
improve an already admissible incumbent is marked `objective_screen`. It skips
collision and transient checking without claiming physical admission. Worthy
trials still pass the original full nonlinear gate; an infeasible incumbent
never enables cost screening. Trial inputs, costs, checks and timing remain in
the prediction records.

The controllers separate an admitted execution sequence from a numerical warm
buffer. Rejected numerical sequences are never directly executed. A failed
refresh still clears the execution sequence, preserves the 100-ms refresh
clock and records recovery on intermediate steps. Numerical retention does not
relabel those steps as normal planning success.

`ch5ReducedRestoreV12` adds at most one elastic feasibility QP after rejection
of all ordinary trials. It minimizes `rho + 1e-5 * norm(delta)^2`; the force
and force-rate rows, terminal linear equalities and correction bounds remain
hard, while other linearized inequalities use a common nonnegative `rho`.
This slack finds a numerical direction. It never relaxes the nonlinear
execution acceptance or the measured physical limits. Recovery QPs are included
in total predictive solve/failure counts and are also reported separately.

v12's first complete nonideal moving-obstacle episode passed physical limits
but failed arrival (final position error 38.44 mm). Expansion stopped, and its
raw episode and source archive are retained. In v13, a failed feasibility-only
search cannot replace the task-generated warm seed; its candidates remain in
diagnostics. This tests a possible cause without changing the task cost or
physical limits. The full closed-loop result below rejected this variant too.

The saved-state audits use the same observations and random-generator states.
With retention/restoration disabled to isolate screening, 14 controller calls
matched v11's executed forces and admitted sequences, and 14 full gates/costs

## Conditioned QP and selective sensitivities (v21)

The adopted development chain is unchanged in its physical decision: four
20-step DDIM control-increment priors -> one local correction of the full
force sequence -> true actuator-augmented rollout -> original full-horizon
and terminal gates -> first force input. Intermediate control still checks
the full executed 20-ms interval. The baseline remains the data teacher and
comparison method; none of these operations introduces an external trajectory
for tracking. Formal four-candidate correction and all-seed evaluation are
still outstanding.

`ch5ReducedSolveV19` factors the condensed Hessian as `Q=L*L'` and changes the
72 numerical correction coordinates by `delta=inv(L')*z`. The resulting
Hessian is close to identity. All original linear constraints and correction
bounds are transformed too. No extra damping, terminal relaxation or physical
slack is added. The nonlinear acceptance objective is unchanged. The returned
step is checked against the original inequalities and equalities, and native
solver exit flags remain visible even when a finite step is usable.

The ten saved matrices had Hessian condition numbers about 1.6e7--2.3e7.
Whitening converged on all ten; the difficult t=3.8 s problems changed from
400 iterations / exit flag 0 to 25 ideal and 31 nonideal iterations / flag 1.
This is a saved-matrix numerical result, not a closed-loop guarantee.
`solver_study_v16` and `dedup_study_v18` retain the unsuccessful terminal-null,
duplicate-row and looser-optimality-tolerance probes. None is enabled in v21.
The dense interior-point V15 probe was terminated for excessive wall time and
is recorded as interrupted, not as a solver-performance result. Do not queue
that diagnostic again without an appropriate wall-time guard. Recovery required one worker restart; later
audits and the whole v21 closed-loop batch reuse PID 38888.

`ch5ReducedJacobianV17` uses fresh true state nodes and updates only those
stage dynamics sensitivities that cannot reuse an aligned previous value.
Reuse requires age <=0.10000001 s, normalized state distance <=0.05, normalized
input distance <=0.2, and local linear prediction residual <=1e-4. At least the
new tail stages are refreshed. Goal changes, failed prediction admission and
task initialization invalidate the cache. Mechanical and obstacle derivatives
remain fresh; the true full/hold/transient physical gates remain mandatory.
These are engineering thresholds inspired by
[partial sensitivity updating](https://arxiv.org/abs/1808.00877), not the
paper's CMoN error-bound mechanism or a transferred convergence proof.

The independent V20 audit passed 16 control replays, two fresh-matrix identity
checks, equilibrium reuse checks, goal/failure cache invalidation, the unchanged
refresh clock and rejection of the previous actuator transient. On equilibrium
reuse of 55 stages, the maximum difference from complete derivatives was below
4.7e-13. That exact-equilibrium check does not bound errors at other states.

`ch5ReducedPriorV21` converts float32 weights to double once per planning call
