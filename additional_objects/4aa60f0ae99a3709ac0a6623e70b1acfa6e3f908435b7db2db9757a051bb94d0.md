# Development probe: reduced force-increment optimization

This folder is an isolated development implementation. It is not the frozen
Chapter 5 experiment version. The registered baseline, trained weights,
teacher data and production configuration remain intact.

## Numerical coordinates and physical decision

The physical decision is still the complete sequence of six-axis branch-force
increments. Applied force commands are accumulated and states are obtained
from the original actuator-augmented `plant.fd`. No independently planned
reference trajectory is handed to a tracking controller.

`ch5ReducedStep` is a diagnostic of straightforward 12-block (72-coordinate)
condensing. `ch5ReducedStepOsqp` changes its QP backend. Both retain a full
60-interval, 1.2-second dynamics horizon and the original physical gate.

`ch5ReducedStepFeedback` additionally preconditions the same correction by
local feedback. For an internally generated warm iterate `(Xbar,Ubar)`,

```
v_j = 160 * sum(block_increment_b, b <= ceil(j/5))
U_j = Ubar_j + v_j - K * (X_j - Xbar_j)
X_(j+1) = fd(X_j, U_j)
DeltaU_j = U_j - U_(j-1)
```

The warm state sequence comes exclusively from dynamics applied to a force
sequence. It is an optimization iterate. These 72 coordinates are a numerical
parameterization of a correction; they must not be described as 72 independent
physical input increments held constant between blocks. The full physical
increments generally vary inside a block. Their nonlinear transformation is
used when generating a trial, and the objective's input/prior terms use the
resulting physical force increments.

In the linearized condensing, `dX_(j+1)=A*dX_j+B*dU_j` and
`dU_j=M_j*dv-K*dX_j`. This avoids propagating only the open-loop `A` in the
numerical sensitivity recursion. The executed first force is checked through
the original dynamics and mesh. This implementation does not constitute a
robust stability or recursive feasibility proof.

The warm-start embedding is informed by Makarow, Roessmann and Bertram,
[Suboptimal nonlinear MPC with input move-blocking](https://arxiv.org/abs/2109.12355).
That paper's guarantees are not asserted for this diffusion/Simscape system.

## Terminal correction and rejection

Preserve and shift the complete previous sequence. Correct only its final
two 100-ms force blocks by Newton iterations for terminal velocity and static
force compatibility. This correction is never an acceptance test. The same
terminal bands, force/rate limits, conservative singularity check, collision
margin and every existing integration point remain required for full-horizon
admission. In v10/v11, intermediate execution instead checks the upcoming
physical hold and does not claim full-horizon or terminal admission.

Endpoint constraints guide the condensed QP. All internal points are audited
afterward; a rejected trial is backtracked. Endpoint linearization alone is
not claimed to guarantee safety between samples.

The restoring fallback retains a pose anchor, clips desired acceleration in
leg space, invokes the baseline safety QP with additional acceleration reserve,
then checks the next complete hold interval. All fallback, failed QP and failed
interval checks remain explicitly uncertified and are recorded.

## Scope and reproducibility

- Control execution: 0.02 s. Optimization refresh: 0.1 s, or goal/visibility change.
- Horizon: 60 intervals, 1.2 s; original internal integration mesh.
- Learned prior: existing validated seed 5101, 20 DDIM steps, four generated
  chains. This speed probe ranks four priors and optimizes one correction.
  It does not implement four independently optimized formal candidates.
- Full cost combines task, physical force/increments and learned-prior terms.
- MATLAB, model and native kernels are reused in one persistent worker.
- Cold preparation and kernel construction are separate from controller time.
- All Simscape development episodes use `CaptureErrors` and save raw records,
  prediction checks, code hashes and actual dense-grid metrics, including failures.
- Formal campaign remains unstarted pending closed-loop and timing acceptance.

Artifacts: `chapter5/artifacts/reduced_probe`. Entry functions are queued via
the existing `ch5SpeedWorker`; do not launch a fresh MATLAB for every episode.

Initial diagnostics and corrected variants are stored in separate artifact
directories. Do not pool them into one result version.

## Corrected full-horizon probe (v9)

`ch5SpeedReducedV9ClosedLoop` writes experiment version `closed_tapered_v9`,
after `ch5SpeedFactorStageAudit` and `ch5SpeedPriorContractV9`. It runs fixed-target, goal-switch and moving-obstacle
tasks in both actuator modes, plus one separately labelled forced-rejection
recovery run. It does not create or consume formal test tasks.

Changes retained in this version:

- `ch5ReducedStepFast` batches the identical 72-coordinate QP matrices. The
  independent reference comparison includes both actuator modes and collision
  constraints; relative differences are below 1e-10.
- `ch5ReducedAuditV4` fixes an optional-argument count error in the old probe:
  the supplied learned prior was reset to zero in posterior cost evaluation.
  QP and posterior objective now use the same physical-increment prior term.
  A nonzero-prior regression checks its exact cost contribution. Version v5's
  closed loops then exposed insufficient arrival performance. In v6, the
  squared physical-increment prior proxy is integrated over time like the
  other running costs: `0.05 * Ts * sum(((DeltaU-prior)/160).^2)`. QP and
  posterior use this identical nonzero term. This is numerical scaling of a
  proxy objective, not the exact diffusion log density.
- `ch5ReducedFactorStage` tested exact chain-rule products through the original
  RK4 substeps for the registered nonideal profile, with the same corrected
  actuator piecewise derivatives. It must pass an independent primal and
  Jacobian comparison before use. The test passed, but was slower (86.74 versus
  79.77 ms per 60-stage batch), so the current controller keeps the original
  derivative kernel. Acceptance always executes original `fd`.
- `ch5ReducedTransient` adds 25, 50, 75, 100, 150 and 200 us actuator checks,
  plus the six slew-ramp end times in every prediction interval. It retains
  the original grid and hard physical limits. These finite extra points are
  not a continuous-time certificate.
- `ch5ReducedRecoveryFast` checks the baseline QP and backtracked commands
  against the next hold interval, including these extra points. It recomputes
  residuals for the force actually executed and records invalid recovery.

The old `closed_latest_v2` startup acceleration failure remains a safety
failure. `closed_fast_v3` records the transient repair without the subsequent
prior-cost correction. The `closed_factor_v4` startup failures exposed an empty
prior at intermediate execution steps; `closed_prior_v5` fixes its dimensions
and first passes a consecutive refresh/intermediate call check. Version v5
failed arrival and remains separate from v6. The `recovery_normalized_v6`
fault-injection episode is separately labelled. Version v6 timing includes
sensor-coordinate conversion, actuator-state prediction and current-state
checks, as well as the complete control computation; older versions exclude
these peripheral steps. No timing includes offline audit or disk journals.

`ch5SpeedReducedV7ClosedLoop` is an unadopted offset-cost test. It adds six
epigraph variables for an L1 offset term, following the local-optimality
discussion in [MPC for tracking, II-D](https://arxiv.org/html/2406.06157v2).
The epigraph/matrix/continuous-call checks passed, but the moving-obstacle
closed loop did not satisfy arrival and had more QP failures. Keep its raw
results separate; do not use it as the current controller or pool it with v6.

Version v8 targeted the observed moving-obstacle failure causes.
It keeps 72 physical correction coordinates, raises the QP iteration limit
from 100 to 400, reserves 0.2 mm in the QP's linearized collision rows, and
raises the running velocity weight from 0.1 to 1. These are development
settings; the original nonlinear physical gate, hard limits and arrival
criteria remain unchanged. The QP and posterior cost use the same new speed
weight. The four independent interface/matrix/cost checks cover both actuator
modes and both absent/present collision rows. Before closed-loop admission,
the checked controller source hashes must match the current source.

Version v9 retains those settings and makes the QP-only additional collision
reserve `0.2 mm * min((prediction_time / 0.1 s)^2, 1)`. Its value and initial
slope are zero at the fixed initial state. Applying the full extra reserve to
that uncontrollable state in v8 created zero-Jacobian infeasible rows. The
nonlinear acceptance gate still requires the original clearance and sample
hold margins, with no relaxation. Separate matrix and objective checks verify
the changed rows and the unchanged cost before running the complete episodes.

`ch5SpeedThreadAudit` separately benchmarks CasADi's documented ThreadMap at
2, 4 and 8 threads on saved moving-obstacle states in both actuator modes.
It compares every stage output, Jacobian and condensed QP matrix against the
serial implementation. Only independent evaluations are parallelized; the
physical state recursion remains sequential. Its timing and numerical audit
must pass before any threaded closed-loop experiment is admitted.
The 12 numerical audits passed, but every measured thread configuration was
slower on this PC. ThreadMap is therefore not enabled in the controller.
This failed performance attempt is preserved separately in `thread_audit_v1`.

## Further multirate development (v10 and v11)

Both revisions keep the same physical model, six branch-force increments,
60-interval optimization, learned prior, terminal bands and hard limits.
Every 100-ms planning refresh still checks the complete original nonlinear
horizon, integration points, actuator transient refinements and terminal
conditions. A 20-ms intermediate execution step checks only the force that
will actually be executed over that interval, using the current state and
current obstacle observation. Its check explicitly has scope
`executed_interval` and `terminal_checked=false`; it does not certify an old
full horizon after feedback or observation changes.

`ch5ReducedHoldKernel` compiles the original one-step physical map and all of
its original mechanical sample values. `ch5ReducedHoldAudit` adds the original
collision threshold, physical force/rate limits and the same transient
refinement. `ch5ReducedAuditGuardedV10` rejects algebraic force/rate violations
before a full rollout. Within a refresh, an exactly identical trial reuses its
check; this cache is not reused across states, observations or control calls.

Version v10 retains an immutable previously admitted prediction between
refreshes and corrects its current force by the numerical local feedback.
The moving pair passed, but ideal fallback increased from 2 to 26 samples;
that negative result is retained in its own artifacts. Version v11 separately
restores v9's dynamics-consistent warm-iterate propagation and necessary tail
correction on intermediate steps. Those propagated futures are numerical
iterates, not fully admitted predictions. Only their current checked hold is
eligible for intermediate execution.

Queue v10 in the persistent worker in this order:

1. `ch5SpeedMultirateAudit`: native/reference hold equivalence, old transient
   rejection, full-gate/nonzero-prior equality, refresh clock and saved failure
   replay. Thirty of the 48 old rejected candidate first holds passed the
   interval check; the complete future remained rejected.
2. `ch5SpeedReducedV10ClosedLoop`: the complete moving-obstacle pair.
3. `ch5SpeedMultirateRemaining`: four fixed/switch cases and forced recovery,
   admitted only after both moving cases safely arrive.

For v11 use `ch5SpeedWarmAuditV11`, `ch5SpeedReducedV11ClosedLoop` and
`ch5SpeedWarmRemainingV11`. Its audit additionally compares intermediate first
forces with v9 whenever v9 admitted its candidate on the same nominal state.
Episode resumption requires matching checked source identities and raw data;
partial or failed episodes are preserved and cannot be silently overwritten.

Recompute each version into a separate report, preserving the v9 report:

```
chapter5/.venv/Scripts/python.exe chapter5/reduced/summarize.py --version closed_multirate_v10
chapter5/.venv/Scripts/python.exe chapter5/reduced/summarize.py --version closed_warm_v11
```

All these are development revisions of the same proposed method, not extra
formal comparison methods. Repeated tasks and revisions are not independent
formal samples. Final inference still needs the complete formal four-candidate
implementation and all registered training seeds.

Measured on 2026-10-08 in the same MATLAB worker (PID 27184), v10 and v11 each
completed all six normal episodes and one forced-rejection recovery episode
with measured safe arrival. The v11 Simscape loop took 27.26--58.57 seconds
per 15-second episode; model preparation and offline dense auditing are extra.
Intermediate complete-controller P95 was 7.75--11.38 ms, but nine of 3,600
intermediate samples exceeded 20 ms (maximum 31.26 ms). Planning P95 was
95.11--523.64 ms, with 574 of 906 refreshes exceeding 100 ms. Neither revision
meets the complete timing requirement or admits the formal campaign.

For the moving-obstacle case, v11 reduced nonideal fallback from v9's 48 to
five samples and predictive QP failures from 24 to 14. Ideal fallback remains
worse than v9 (five versus two), although it recovered v10's regression to
26; ideal predictive QP failures changed from 17 to nine. This is a tradeoff,
not uniform improvement. No per-case mix of versions was selected. The v11
nonideal moving-case median backtracking checks took 100.23 ms and native
stage derivatives 64.81 ms; these remain the main measured bottlenecks.
