# Full-horizon conditional diffusion + IHSID

Independent experiment based on mainline `ae06b75`. Static rigid-body Stewart model, fixed start, goal pose and duration conditions, cylinder/environment collision only. Every obstacle and the final hood gap use **10 mm**. There is no prescribed insertion phase, contact model, or Simscape validation in this experiment.

## Run

In MATLAB, add this directory and call:

```matlab
c = setupDiffusion();
test_diffusion_core;
run_stage1;
run_dp_worker('pilot',1,1,'pilot_v1'); % freeze 12 task groups
run_dp_worker('data',1,2,'pilot_v1');  % independent MATLAB worker 1
run_dp_worker('data',2,2,'pilot_v1');  % independent MATLAB worker 2
run_dp_worker('export',1,1,'pilot_v1');
```

Train the actual DDPM with `train_diffusion.py DATASET OUTPUT --device cuda`, then run `run_dp_worker('benchmark',1,1,'pilot_v1')` and `renderDiffusionResults('pilot_v1')`. The training output must be under that run's `training` directory.

On the development Windows computer, `remote.ps1 -Action deploy` copies only source into the independent remote directory. `remote.ps1 -Action pipeline -RunName pilot_v1` runs the staged pilot on `ws`; use a name beginning with `formal` for 100 frozen task groups (70/10/20 split). Keep the SSH session alive. Outputs/checkpoints persist after a connection failure and the same pipeline can resume. Run `remote.ps1 -Action collect -RunName pilot_v1` to retrieve that run under `results/remote/diffusion`. Formal expansion follows a reviewed successful pilot; the pipeline does not automatically launch another dataset.

`STEWART_DEPENDENCY_ROOT` points to a checkout containing the existing CasADi 3.7.2 and CoinHSL binary dependencies. Remote computation uses its existing isolated Python/CUDA environment and MATLAB R2019a. No original project files or installed environments are overwritten. At most two MATLAB data workers run concurrently.

## Definitions

- 16 quintic B-spline controls; the first/last three enforce stationary endpoints. The 60 free coordinates are offsets from a minimum-jerk endpoint interpolant.
- Formal target perturbations apply directly to the platform goal position (each coordinate within 40 mm) and RPY (each within 8 degrees). The target assembly is positioned consistently with that goal and the 10 mm clearance. Pilot v4 perturbed the assembly center, which also introduced rotation-dependent endpoint translation; that development snapshot is kept distinct.
- Full-horizon implicit Hermite-Simpson optimization has 60 intervals, free acceleration and force variables, and cylinder/OBB support-plane certificates. A 1 mm interior optimization cushion tapers to zero at the endpoints; the acceptance distance remains 10 mm.
- Exact Hessians replace the initial limited-memory numerical configuration after development showed poor convergence. This changes solver numerics, not the objective or acceptance thresholds.
- Independent distance verification enumerates box-axis, cylinder-axis, side-circle vertex-projection and edge-boundary normals. A free two-angle refinement is used when these do not certify the required gap. It does not reuse NLP separation variables. Gaps are conservative separation certificates; no exact penetration-depth or continuous-time safety claim is made.
- Position reconstruction uses quintic Hermite segments matching node position, velocity and acceleration, including stationary endpoint accelerations. Both interpolated IHSID forces and the unclipped forces needed by reconstructed geometric motion are checked. Dense dynamics disagreement is reported separately.
- A plain least-squares spline fit is revalidated; when it loses feasibility, bounded physical-gradient projection first attempts a small repair, followed by a full constrained fit if needed. Every repaired curve is independently revalidated. Failed fits never enter the training set. Pilot v3 used the original direct constrained-fit fallback; the faster fitting path is a subsequent development change, validated on completed training samples before formal expansion.
- Guidance uses normalized collision, leg kinematics, demand force, regularized inverse-Gram trace, and curve regularity. It updates the predicted clean sample during the last 20 denoising steps, every other step, with backtracking and fixed endpoints.
- Three methods share task conditions, 8 candidate maximum, sorting, optimizer, stopping rule and dense acceptance. The two diffusion methods share trained weights and initial noise. Offline costs are separate from full online wall time.
- The offline teacher uses bounded physical preparation of geometric starts to stabilize dataset generation. Failed preparation retains the original start rather than suppressing the attempt. The formal traditional baseline follows the requested protocol: eight raw geometric starts, followed by the common ranking, IHSID and posterior checks. Pilot v4 included physical preparation in its traditional baseline and timed that extra work; its development timings must not be presented as the formal raw-geometric baseline.
- Repeated candidates for the same task reuse the symbolic NLP with the candidate reference supplied as a parameter. The cache key includes the full task, solver options and grid. Benchmarking clears this cache before each method, so every method pays its own first build; candidate preparation and later build reuse are both timed. This cache is a subsequent change for formal expansion; pilot v4 retains its earlier implementation snapshot.

## Evidence and limitations

The authoritative state is `results/diffusion/<run>/pipeline_status.json`, the frozen manifest, attempt MAT files, actual model asset and benchmark records. `core_tests.json` only certifies numerical interfaces; it does not certify trained performance. `benchmark_complete.json` means the scheduled comparisons finished, including failures; successful delivery additionally requires one guided held-out success from each scene family and visibly distinct candidates.

`auditDiffusionDelivery(runName)` writes `delivery_audit.json` and `paired_guidance.csv`: it checks actual model provenance, MATLAB/Python network agreement, complete attempt records, accepted trajectories from both scene families, and matched noise/weights with accepted decreasing-cost guidance updates. It reports summed offline attempt wall time separately from online benchmark time. This numerical audit does not replace visual review of the eight candidates and rendered animations.

Formal benchmark tasks are split between two independent MATLAB processes. Each process evaluates the three methods sequentially for its assigned tasks and writes separate summary shards; merging verifies every result fingerprint. Reported online wall time is measured inside each method under this two-process execution setting. Pilot v4 used the earlier serial benchmark runner.

Use a new run directory after implementation/config/task changes. The data worker refuses mismatching fingerprints. Debug only on development/validation tasks; do not tune against the frozen formal test tasks. Failed solver attempts and nonfinite candidates remain in records. No fallback force clipping, relaxed acceptance, changed task duration, synthetic model weights or silent baseline substitution is used.
